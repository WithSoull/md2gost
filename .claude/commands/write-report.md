# Отчёт для md2gost

Используй для Markdown-отчётов и дипломов, которые собираются этим проектом. Оформление основано на предоставленных правилах («ПРАВИЛА_ОФОРМЛЕНИЯ.docx»), а не на полном автоматическом контроле ГОСТ. Перед работой прочитай `analysis/formatting-rules.md`: там параметры, согласованные исключения для таблиц и листингов и устройство финальной вёрстки.

## Исходные данные

Сначала изучи доступные материалы и запрос пользователя. Спроси только то, чего не хватает для содержания: тему, автора, структуру, исходники, источники. Не запрашивай заново известные сведения и не останавливай редактирование готового документа из-за пустого титульного блока. Не придумывай результаты экспериментов, источники, согласования и данные автора. При правках конвертера не переписывай содержание диплома без поручения: о нарушениях правил в тексте сообщай, а не исправляй молча.

## Markdown

Метаданные в начале файла:

```yaml
---
title: "Название работы"
author: "Фамилия И.О."
date: "2026-10-22"
lang: ru
---
```

Дату и автора бери из задания. `lang: ru` задаёт язык документа; переносы слов в профиле отключены. При отдельно подготовленном титульнике используй `--no-title-page`, не создавай вместо него произвольный титульный лист.

Заголовки пиши без ручных номеров:

```markdown
# Введение
## Название раздела
### Название подраздела
#### Название пункта
# Заключение
# Список использованных источников
# Приложения
# Приложение А. Название приложения
```

`#` — структурные части без номера, по центру, прописными. `##` → раздел `1 НАЗВАНИЕ РАЗДЕЛА` (18 пт, с новой страницы), `###` → `1.1 Название подраздела` (16 пт), `####` → `1.1.1 Название пункта` (14 пт). Разделы выровнены по ширине, с первой строкой 1,25 см. Не пропускай уровни. Заголовок начинается с прописной буквы и не заканчивается знаком препинания.

Перед списком оставляй пустую строку. Нумерованные пункты начинаются с прописной буквы и заканчиваются точкой. Маркированные — со строчной, разделяются точками с запятой, последний заканчивается точкой; явные пожелания пользователя к тексту имеют приоритет. Сноски внизу страницы запрещены. Источники перечисляй в порядке упоминания, их не меньше семи; ссылки — `[1]`, `[2, с. 15]`; проверь фактические библиографические данные.

Типографика (п. 1.10–1.11): тире между словами — «—» с пробелами; «–» — минус, «-» — дефис, в том числе в диапазонах. Прямые кавычки `"…"` конвертер сам превратит в «…» (в английском тексте — в “…”), вложенные пиши как `'…'`.

## Рисунки и таблицы

Первое упоминание размещай перед соответствующим объектом. Он может оказаться на следующей странице. Слово в нужном падеже с большой буквы пишет автор, `@fig:` и `@tbl:` выводят только номер.

```markdown
Структура показана на Рисунке @fig:schema.

![Структура системы](images/schema.png){#fig:schema}

Результаты приведены в Таблице @tbl:results.

: Результаты измерений {#tbl:results}

| Параметр | Значение | Единица |
|---|---|---|
| Время | 5 | с |
```

В конце названий рисунков и таблиц точка не ставится. Крупные рисунки конвертер пропорционально ограничивает высотой 19 см на книжной странице и 14 см на альбомной. Проверь читаемость надписей после уменьшения. Пути разрешаются относительно Markdown, кириллица в путях допустима.

Подпись таблицы — 12 пт курсивом, перед ней 6 пт, после 0; после таблицы 6 пт. По согласованию с пользователем таблица идёт после упоминания без обязательной новой страницы. Шапка по центру, первый столбец слева, остальные по ширине. Равные разделители столбцов включают автоподбор по содержимому: короткая таблица остаётся уже текста по центру, широкая занимает всю ширину. Неравные разделители сохраняют заданные пропорции.

Для ручного разрыва: `: Результаты {#tbl:results break-after="5,10"}` — числа означают строки данных, шапка не считается. Не назначай разрывы по предполагаемому числу строк на странице. Для финальной сборки используй `--paginate`: таблица делится ровно по странице с подписью «Продолжение Таблицы 1.1».

## Формулы

```markdown
Энергия определяется по формуле @eq:energy.

$$
E = mc^2,
$$ {#eq:energy}

где $E$ — энергия, Дж;
$m$ — масса, кг;
$c$ — скорость света, м/с.
```

Номер получает только формула с меткой, на которую есть ссылка в документе. Формулы остаются редактируемыми OMML, номер справа. До и после формулы — одна строка (24,15 пт). Перед «где» формула заканчивается запятой внутри `$$`, в конце предложения — точкой. Каждое обозначение после «где» пиши с новой строки без пустых строк. Конвертер поставит «где» без отступа и выровняет обозначения табуляцией одно под другим. Это работает и после формулы без номера. Порядок объяснений и единицы проверяет автор.

## Приложения и листинги

````markdown
# Приложения

# Приложение А. Исходный код модуля

Код приведён в Листинге А.1.

```
Листинг А.1 — Основная функция
print("Hello")
```

## Тестовые данные
````

Пустая часть `# Приложения` получает автоматический перечень приложений. «Приложение А» печатается полужирным с новой страницы, название — следующей строкой обычным, оба по центру, интервалы 0. Название можно отделить точкой или тире либо задать блоком `::: {custom-style="Appendix Title"}`. `##` внутри приложения — раздел «Приложение А.1» с названием на следующей строке. Для обозначений не используй Ё, З, Й, О, Ч, Ь, Ы, Ъ. На каждое приложение должна быть ссылка в тексте.

Первая строка блока листинга начинается с `Листинг`, иначе блок получит только моноширинный шрифт без подписи и рамки. Нумерацию листингов задаёт автор. Подпись 12 пт курсивом слева, без новой страницы; код Courier New 10 пт в рамке, после листинга 6 пт. Чтобы ссылаться на строки кода, добавь `{.numberLines}`: строки получат номера 10, 20, 30… При финальной сборке длинный листинг делится по странице с подписью «Продолжение Листинга А.1»; вручную — `break-after="40"` в атрибутах блока.

## Сборка и проверка

Сохрани Markdown в согласованном месте. Выполни сборку без повторного запроса разрешения:

```bash
md2gost convert report.md --no-title-page -o report.docx
```

Разбери предупреждения валидатора. Нарушения в тексте автора (запятая перед «где», тире, регистр пунктов, ссылки на приложения) перечисли пользователю и исправляй только с его согласия.

Финальная сборка встроенным профилем:

```bash
md2gost convert report.md --no-title-page --paginate -o report.docx
```

Нужны LibreOffice 7.4+ (`soffice` в PATH или `--libreoffice /путь/к/soffice`) и `pypdf` из extra `pagination`. Режим измеряет страницы по закладкам PDF, заполняет оглавление, делит таблицы и листинги, а при пустоте в конце страницы перед высоким рисунком уменьшает его (не меньше 75 %) или переносит перед ним следующие абзацы в пределах подраздела. Сообщи пользователю, какие абзацы переставлены; если порядок должен остаться авторским, собери с `--keep-order`.

Отрендери DOCX в PDF (`soffice --headless --convert-to pdf`) и просмотри все страницы: нет ли обрезки, пустых листов, оторванных подписей, переполнения формул, неверных продолжений таблиц и листингов, крупных пустот внутри подразделов. В быстрой сборке оглавление требует обновления полей в Word. В финальной номера относятся к LibreOffice и установленным шрифтам: Word может сдвинуть разрыв на строку. При изменении текста или редактора повтори проверку. Сообщи путь к результату, выполненные проверки и оставшиеся ограничения. Не обещай идеальное соответствие только по коду возврата конвертера.
