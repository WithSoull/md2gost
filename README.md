# md2gost

Конвертер Markdown → DOCX для учебных отчётов и дипломов. Встроенное оформление настроено по разобранному образцу ВКР Оленина: А4, поля 30/10/20/20 мм, Times New Roman 14 пт, интервал 1,5, абзац 1,25 см. Утилита нумерует разделы, таблицы, рисунки и формулы, оформляет приложения и листинги. Основание настроек и ограничения образца описаны в [памятке](analysis/olenin-diploma-formatting.md); это не автоматическая проверка соответствия всем стандартам и требованиям кафедры.

## Установка

### macOS (Homebrew) — рекомендуется

```bash
brew tap WithSoull/md2gost https://github.com/WithSoull/md2gost
brew install md2gost
```

Всё. Pandoc, pandoc-crossref и Python-зависимости подтянутся автоматически.

### Ручная установка

1. Поставь pandoc и pandoc-crossref:

```bash
# macOS
brew install pandoc pandoc-crossref

# Ubuntu/Debian
sudo apt install pandoc
# pandoc-crossref: скачай бинарник с https://github.com/lierdakil/pandoc-crossref/releases

# Windows
choco install pandoc
# pandoc-crossref: скачай .exe с https://github.com/lierdakil/pandoc-crossref/releases и положи в PATH
```

2. Установи md2gost:

```bash
git clone https://github.com/WithSoull/md2gost.git
cd md2gost
```

**С uv (быстрее всего):**

```bash
uv venv && uv pip install -e .
source .venv/bin/activate
```

**С pip:**

```bash
python3 -m venv .venv
.venv/bin/pip install -e .
source .venv/bin/activate
```

**С pipx (глобально, без venv):**

```bash
pipx install .
```

## Использование

```bash
# Базовая конвертация
md2gost convert report.md

# Указать выходной файл
md2gost convert report.md -o ~/Desktop/отчёт.docx

# Без оглавления
md2gost convert report.md --no-toc

# Без титульного блока (title, author и date остаются в YAML)
md2gost convert report.md --no-title-page

# Начать нумерацию с 5 (если предыдущие листы подготовлены отдельно)
md2gost convert report.md --no-title-page --page-start 5

# Свой шаблон
md2gost convert report.md -t my_template.docx

# Пропустить валидацию
md2gost convert report.md --no-validate

# Watch-режим — пересобирает при каждом сохранении
md2gost watch report.md
```

## Как писать Markdown для ГОСТ

### Шапка файла (рекомендуется)

```yaml
---
title: "Название отчёта"
author: "Иванов И.И."
date: "2026-04-25"
lang: ru
---
```

### Структура заголовков

```markdown
# Введение              ← ненумерованный, ЗАГЛАВНЫЕ в DOCX, с новой страницы
## Теоретическая часть   ← станет «1 ТЕОРЕТИЧЕСКАЯ ЧАСТЬ»
### Подраздел            ← станет «1.1 Подраздел»
#### Пункт              ← станет «1.1.1 Пункт»
## Практическая часть    ← станет «2 ПРАКТИЧЕСКАЯ ЧАСТЬ»
# Заключение            ← ненумерованный
# Список использованных источников
# Приложение А
```

**Правила:**
- `#` — только для спец-разделов без номера (Введение, Заключение, Реферат, Список источников, Приложение)
- `##`, `###`, `####` — нумерованные разделы, подразделы и пункты; в Word они получают уровни 1, 2, 3 и шрифт 18, 16, 14 пт. Основные разделы начинаются с новой страницы.
- Структурные заголовки `#` центрируются и начинаются с новой страницы; номера основных глав не сбрасываются. Аннотация не включается в оглавление.
- Остальные структурные части, включая введение и заключение, включаются в оглавление.
- Не пиши номера вручную — фильтр сделает это сам

### Рисунки

```markdown
На @fig:schema показана архитектура системы.

![Архитектура системы](images/schema.png){#fig:schema}
```

> `@fig:schema` автоматически превратится в «рис. 1.1». Не пиши «на рисунке @fig:schema» — получится «на рисунке рис. 1».

Рисунок получает подпись снизу: «Рисунок 1.1 – Название», 12 пт, полужирный, по центру. Счётчик начинается заново в каждой главе и приложении. Относительные пути к изображениям разрешаются от папки Markdown-файла.

### Таблицы

```markdown
Результаты приведены в @tbl:results.

: Результаты эксперимента {#tbl:results}

| Метод   | Точность |
|---------|----------|
| GCN     | 0.82     |
| GAT     | 0.85     |
```

Подпись таблицы размещается сверху слева, 12 пт, курсив; после подписи — 6 пт. После самой таблицы — также 6 пт; больший интервал перед следующим заголовком сохраняется. В ячейках — 12 пт, одинарный интервал; текст в шапке полужирный и выровнен по центру, в остальных ячейках — по ширине; границы видимые. При переносе повторяется шапка. Таблицы нумеруются внутри главы или приложения, в том числе таблицы с подписью без идентификатора. Ссылка `@tbl:results` превращается в «табл. 1.1».

### Формулы

```markdown
Оценка внимания вычисляется по @eq:attention.

$$
\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$ {#eq:attention}
```

Формула остаётся редактируемой формулой Word; её номер `(1.1)` стоит справа на той же строке, сама формула — по центру. В приложении используется `(А.1)`. Ссылка `@eq:attention` заменяется на `(1.1)`. После формулы нужно самостоятельно написать пояснения обозначений со словом «где».

### Листинги кода (в приложениях)

Первая строка блока кода — подпись листинга:

````markdown
# Приложение А

Исходный код на Python.

```
Листинг А.1 – Основной модуль
import torch
import torch.nn as nn

class Model(nn.Module):
    def __init__(self):
        super().__init__()
        ...
```
````

Код оформляется Courier New 10 пт, одинарным интервалом, слева, в рамке. Длинные листинги разбиваются на фрагменты с подписями «Продолжение листинга А.1 – Основной модуль» и «Окончание листинга А.1 – Основной модуль». Фрагмент удерживается с подписью; при выборе размера учитываются длины строк. Обычные блоки кода также получают Courier New 10 пт, но не подпись и рамку.

### Список литературы

```markdown
# Список использованных источников

1. Иванов И.И. Название книги. — М.: Издательство, 2024. — 200 с.
2. Петров П.П. Название статьи // Журнал. — 2023. — Т. 5, № 2. — С. 10–15.
```

### Название приложения

```markdown
# Приложение А

::: {custom-style="Appendix Title"}
Организационно-экономическое обоснование
:::
```

Обозначение и название приложения — отдельные строки, 14 пт, полужирные, по центру. Таблицы и рисунки внутри получают номера `А.1`, `А.2`. Текст названия и порядок приложений задаёт автор.

### Альбомные страницы

```markdown
::: {.landscape}

: Широкая таблица {#tbl:wide}

| Параметр | Описание |
|----------|----------|
| Пример | Данные |

:::
```

Блок внутри `.landscape` размещается на альбомных листах А4: поля сверху 30 мм, снизу 10 мм, слева и справа 20 мм. После блока возвращается книжная ориентация; номера страниц продолжаются. Используй отдельные последовательные блоки, не вкладывай `.landscape` друг в друга. Поддержка этих вставок и `--page-start` относится к встроенному шаблону.

### Оглавление и границы автоматизации

При наличии `# Аннотация` оглавление располагается после неё. Оно содержит названия структурных частей и до трёх уровней разделов, ссылки и точечные заполнители. **После открытия в Word обнови оглавление целиком**: до обновления вместо номеров страниц отображается «—». В файле также установлено обновление полей при открытии. Окончательные номера зависят от редактора, шрифтов и разбиения на страницы.

Для `.docx`, собранного с `--template`, сохраняются настройки пользовательского reference-документа; встроенный профиль поверх них не накладывается. Нумерация заголовков и медиа по Markdown-конвенциям продолжает работать.

Утилита оформляет предоставленный материал: аннотацию, источники, объяснения формул, экономические расчёты, сканы справок и подписи не сочиняет. Она не устанавливает минимальный объём, количество источников или порог оригинальности. Длинные таблицы используют повторение шапки; отдельные надписи «Продолжение таблицы» автоматически не добавляются. После сборки нужно просмотреть длинные таблицы, изображения и листинги в целевом редакторе.

### Проверка изменений

```bash
.venv/bin/pytest tests/ -q
md2gost convert tests/fixtures/formatting/diploma.md --no-title-page -o /tmp/check.docx
```

Проверочный документ охватывает подписи, прямые и опережающие ссылки, формулы основной части и приложения, длинный листинг, многостраничную альбомную таблицу и возврат к книжной ориентации.

## Использование с Claude Code

[Claude Code](https://claude.ai/code) — AI-ассистент в терминале, который умеет писать и редактировать отчёты за тебя.

### Установи скилл (один раз)

Скилл — это инструкция для Claude, как правильно писать отчёт по ГОСТ. Добавь alias в `~/.zshrc` (или `~/.bashrc`):

```bash
echo 'alias gost-skill="mkdir -p .claude/commands && curl -sL https://raw.githubusercontent.com/WithSoull/md2gost/main/.claude/commands/write-report.md -o .claude/commands/write-report.md && echo write-report skill installed"' >> ~/.zshrc
source ~/.zshrc
```

### Используй

1. Перейди в директорию с проектом, где нужен отчёт:

```bash
cd ~/my-project
```

2. Установи скилл в этот проект:

```bash
gost-skill
```

3. Запусти Claude Code и вызови скилл:

```bash
claude
```

В чате набери:

```
/write-report
```

Claude задаст вопросы про тему, автора, разделы — и сгенерирует готовый `.md` файл, а затем сам сконвертирует его в `.docx`.

### Что умеет скилл

- Задаёт вопросы и генерирует полноценный `.md` по ГОСТ 7.32
- Правильно оформляет рисунки, таблицы, формулы, листинги
- Автоматически запускает `md2gost convert` после генерации
- Можно попросить отредактировать уже существующий отчёт
