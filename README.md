# md2gost

Конвертер Markdown → DOCX для учебных отчётов и дипломов. Встроенный профиль настроен по предоставленному документу «ПРАВИЛА ОФОРМЛЕНИЯ»: А4, поля 30/10/20/20 мм, Times New Roman 14 пт, интервал 1,5, абзац 1,25 см. Основания настроек, согласованные исключения и границы автоматизации описаны в [памятке](analysis/formatting-rules.md).

## Установка

Установи [uv](https://docs.astral.sh/uv/getting-started/installation/), [Git](https://git-scm.com/downloads), [Pandoc 3.8+](https://pandoc.org/installing.html) и [pandoc-crossref](https://github.com/lierdakil/pandoc-crossref/releases). Все четыре команды должны быть доступны в `PATH`. Версия Pandoc должна совпадать с той, что указана после `built with Pandoc` в выводе `pandoc-crossref --version` ([требование pandoc-crossref](https://github.com/lierdakil/pandoc-crossref#installation)).

Дальше одинаково на macOS, Linux и Windows:

```bash
uv tool install --python 3.13 "git+https://github.com/WithSoull/md2gost.git@main"
uv tool update-shell
```

uv установит Python 3.13 и зависимости. Открой новый терминал и проверь:

```bash
pandoc --version
pandoc-crossref --version
md2gost --help
```

Обновление до текущей версии из `main`:

```bash
uv tool upgrade md2gost
```

## Использование

```bash
# Базовая конвертация
md2gost convert report.md

# Указать выходной файл
md2gost convert report.md -o ~/Desktop/отчёт.docx

# Без оглавления
md2gost convert report.md --no-toc

# Без титульного блока (title, author и date остаются в YAML)
md2gost convert report.md --no-title-page

# Начать нумерацию с 5 (если предыдущие листы подготовлены отдельно)
md2gost convert report.md --no-title-page --page-start 5

# Свой шаблон
md2gost convert report.md -t my_template.docx

# Пропустить валидацию
md2gost convert report.md --no-validate

# Watch-режим — пересобирает при каждом сохранении
md2gost watch report.md
```

## Вёрстка по LibreOffice (`--paginate`)

> **Если работа сдаётся в Word, не используй этот режим.** Он раскладывает страницы так, как их видит LibreOffice, а Word укладывает строки таблиц иначе. В Word подпись «Продолжение Таблицы» может оказаться посреди страницы, а перед ней останется пустота. Для Word собирай без `--paginate`: открой файл, обнови поля (оглавление), посмотри, где рвутся длинные таблицы, и укажи эти места в подписях через `break-after` (см. «Таблицы»). Режим полезен, только если итоговый PDF печатается из LibreOffice.

Дополнительно установи LibreOffice (7.4 или новее) и зависимость для чтения результатов вёрстки:

```bash
uv tool install --reinstall --python 3.13 "md2gost[pagination] @ git+https://github.com/WithSoull/md2gost.git@main"
md2gost convert diploma.md --no-title-page --paginate
```

`--paginate` раз за разом экспортирует временный PDF и измеряет вёрстку по закладкам, которые LibreOffice выгружает с точным положением на странице. Текст при этом не сопоставляется. Затем исправляется самая ранняя проблема, и измерение повторяется:

- таблица или листинг, пересекающие границу страницы, делятся ровно по ней; продолжение получает подпись «Продолжение Таблицы 2.1» или «Продолжение Листинга А.1». Шапка таблицы повторяется, а нижняя граница первой части не проводится (п. 6.3);
- если крупный рисунок не поместился после упоминания, ушёл на следующую страницу и оставил пустоту в четыре строки и больше (п. 1.7), рисунок немного уменьшается, когда это помогает (до 80 %, при отсутствии другого выхода — до 75 %). Иначе текст после подписи переносится перед рисунком, и рисунок открывает следующую страницу (п. 1.14). Переносятся только обычные абзацы и списки вместе с вводной фразой и только в пределах подраздела;
- номера страниц оглавления берутся из закладок заголовков.

Флаг `--keep-order` запрещает переставлять абзацы: остаётся только уменьшение рисунков.

Если `soffice` не найден в PATH, укажи его через `--libreoffice /путь/к/soffice`. Без `--paginate` остаётся быстрая сборка без дополнительной зависимости: таблицы переносятся только с повтором шапки, оглавление обновляется в Word. Пустота остаётся, если высокий рисунок закрывает подраздел и перенести перед ним нечего.

## Как писать Markdown для ГОСТ

### Шапка файла (рекомендуется)

```yaml
---
title: "Название отчёта"
author: "Иванов И.И."
date: "2026-04-25"
lang: ru
---
```

### Структура заголовков

```markdown
# Введение              ← ненумерованный, ПРОПИСНЫМИ, по центру, с новой страницы
## Теоретическая часть   ← «1 ТЕОРЕТИЧЕСКАЯ ЧАСТЬ», 18 пт, с новой страницы
### Подраздел            ← «1.1 Подраздел», 16 пт
#### Пункт              ← «1.1.1 Пункт», 14 пт
## Практическая часть    ← «2 ПРАКТИЧЕСКАЯ ЧАСТЬ»
# Заключение            ← ненумерованный
# Список использованных источников
# Приложения
# Приложение А. Название приложения
```

**Правила (таблица 2.1, п. 2.6.7):**
- `#` — только для структурных частей без номера: аннотация, введение, заключение, список источников, приложения.
- `##`, `###`, `####` — разделы, подразделы и пункты; в Word они получают уровни 1, 2, 3, полужирный шрифт 18, 16, 14 пт, отступ первой строки 1,25 см, интервалы 0/24/24 пт до и 12 пт после. Разделы начинаются с новой страницы, их названия печатаются эффектом «Все прописные».
- Структурные части центрируются и начинаются с новой страницы; номера глав не сбрасываются. Аннотация не включается в оглавление, остальные структурные части включаются.
- Номера вручную не пиши — фильтр расставит их сам.

### Рисунки

```markdown
Архитектура системы показана на Рисунке @fig:schema.

![Архитектура системы](images/schema.png){#fig:schema}
```

`@fig:schema` превращается только в номер: «на Рисунке 1.1». Слово «Рисунок» в нужном падеже и с заглавной буквы пишет автор. Если перед `@fig:` нет слова, начинающегося с «Рисун», валидатор выдаст предупреждение; сборка при этом не прерывается.

Подпись ставится под рисунком: «Рисунок 1.1 — Название», 12 пт, полужирный, по центру, после неё 6 пт (таблица 7.1). Счётчик начинается заново в каждой главе и приложении. Относительные пути к изображениям разрешаются от папки Markdown-файла. Крупные рисунки пропорционально уменьшаются до ширины текста и высоты 19 см на книжной странице (14 см на альбомной), чтобы рядом поместились вводный текст и подпись. Это настройка вёрстки, а не размер из правил. Изображения не увеличиваются.

Рисунок удерживается только со своей подписью. Абзац с упоминанием к рисунку не привязан: если рисунок не помещается, он переходит на следующую страницу (п. 1.14), а заголовок и абзац остаются на месте. Иначе заголовок, длинный абзац и высокий рисунок образовали бы цепочку «не отрывать от следующего» длиннее страницы, и Word оставлял бы пустоту сразу на двух страницах. Оставшуюся пустоту перед высоким рисунком убирают уменьшением рисунка (`{#fig:id height=13cm}`) или переносом следующего абзаца перед ним в Markdown.

### Таблицы

```markdown
Результаты приведены в Таблице @tbl:results.

: Результаты эксперимента {#tbl:results}

| Метод   | Точность |
|---------|----------|
| GCN     | 0.82     |
| GAT     | 0.85     |
```

Подпись ставится над таблицей: «Таблица 1.1 — Название», 12 пт, курсив, по ширине, до неё 6 пт, после 0 (таблица 6.1). По согласованию таблица идёт сразу после упоминания, без обязательной новой страницы. После таблицы — 6 пт (п. 6.6); больший интервал перед следующим заголовком сохраняется. В ячейках 12 пт, одинарный интервал. Шапка полужирная и центрирована, первый столбец (заголовки строк) выровнен влево, остальные ячейки — по ширине. При переносе повторяется шапка. Поля ячеек: сверху и снизу около 1 мм, слева и справа 0,19 см. Таблицы нумеруются внутри главы или приложения, включая таблицы с подписью без идентификатора. Ссылка `@tbl:results` выводит только номер «1.1».

Если в Markdown все столбцы одинаковые (обычный `|---|---|`), ширина подбирается по содержимому (п. 6.4). Учитывается видимый текст ячеек, включая символы формул. Короткая таблица остаётся уже текста и стоит по центру. Широкая занимает всю ширину текста (17 см на книжном листе, 25,7 см на альбомном) и переносит самые длинные ячейки, не разрывая слов. Неравные ширины, заданные числом дефисов, и листинги не меняются.

Подпись «Продолжение Таблицы» (п. 6.3) ставится так: `: Название {#tbl:id break-after="5,10"}` — новые части начнутся с новой страницы после пятой и десятой строк данных, шапка не считается. Номера строк бери из документа, открытого в том редакторе, в котором сдаётся работа, когда текст перед таблицей уже не меняется.

### Формулы

```markdown
Оценка внимания вычисляется по формуле @eq:attention.

$$
\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V,
$$ {#eq:attention}

где $Q$ — матрица запросов;
$K$ — матрица ключей;
$V$ — матрица значений;
$d_k$ — размерность ключа.
```

Нумеруются только формулы с меткой, на которую ссылается `@eq:…` (п. 5.6). Формула остаётся редактируемой формулой Word: она стоит по центру, номер `(1.1)` — справа на той же строке, в приложении — `(А.1)`. Ссылка `@eq:attention` заменяется на «(1.1)». Над формулой и под ней оставлена одна пустая строка основного текста (п. 5.2): 24,15 пт, ровно шаг строки Times New Roman 14 пт с интервалом 1,5. Это интервал абзаца, пустых абзацев нет.

Абзац сразу после отдельной формулы, начинающийся со слова «где», разбивается по строкам исходника (п. 5.8). «где» стоит без отступа и без двоеточия, а все обозначения начинаются от одной позиции табуляции 1,25 см, одно под другим. Поэтому каждое обозначение пиши с новой строки без пустых строк. Формула не отрывается от пояснения на другую страницу. Знак препинания после формулы ставит автор (п. 5.4): перед «где» — запятая внутри `$$…$$`; при её отсутствии валидатор предупредит.

### Листинги кода

Первая строка блока кода — подпись листинга:

````markdown
Основной модуль приведён в Листинге А.1.

```
Листинг А.1 — Основной модуль
import torch

class Model(torch.nn.Module):
    ...
```
````

Подпись: 12 пт, курсив, слева, до неё 6 пт; дефис или «–» после номера заменяются тире (п. 8.2). Код — Courier New 10 пт, одинарный интервал, в рамке (п. 8.4); после листинга 6 пт (п. 8.6). Каждая строка кода — отдельная строка таблицы-рамки, поэтому `--paginate` делит длинный листинг точно по странице и подписывает продолжение «Продолжение Листинга А.1». Для ручного деления подходит `break-after` в атрибутах блока: ```` ```{break-after="40"} ````. Чтобы ссылаться на отдельные строки (п. 8.3), добавь класс `.numberLines`: строки получат номера 10, 20, 30… Блоки кода без подписи «Листинг» получают Courier New 10 пт без рамки. Как и для таблиц, подпись листинга не начинает новую страницу: так в примере самих правил (Приложение А.3) и по п. 1.7.

### Список литературы

```markdown
# Список использованных источников

## Нормативные документы

1. Иванов И.И. Название книги. — М.: Издательство, 2024. — 200 с.

## Книги

2. Петров П.П. Название статьи // Журнал. — 2023. — Т. 5, № 2. — С. 10–15.
```

Записи оформляются основным текстом: номер с отступом 1,25 см, перенос строки к левому полю (п. 9.4). Необязательные рубрики `##` внутри списка не нумеруются, не попадают в оглавление и оформляются по таблице 9.1: 14 пт, обычный, все прописные, по центру, 6 пт до и после. Порядок источников и библиографическое описание задаёт автор; валидатор напомнит, если источников меньше семи (п. 9.2).

### Приложения

```markdown
# Приложения

# Приложение А. Организационно-экономическое обоснование

Текст приложения.

## Расчёт затрат

# Приложение Б — Исходный код
```

Если структурная часть `# Приложения` пуста, на её первом листе автоматически печатается перечень «Приложение А — Название» (п. 10.3). Обозначение «Приложение А» печатается полужирным 14 пт по центру с новой страницы, название — следующей строкой обычным шрифтом по центру, интервалы 0 (п. 10.7). Название можно отделить точкой или тире, а можно оформить блоком `::: {custom-style="Appendix Title"}`. Разделы `##` внутри приложения становятся «Приложение А.1» с названием на следующей строке (п. 10.4), пункты `###` — «А.1.1 Название». Таблицы, рисунки и формулы нумеруются по букве приложения: «Таблица А.1», «Рисунок Б.5» (п. 10.5). Буквы Ё, З, Й, О, Ч, Ь, Ы, Ъ не используются; на каждое приложение должна быть ссылка в тексте (п. 10.6) — иначе валидатор предупредит.

### Альбомные страницы

```markdown
::: {.landscape}

: Широкая таблица {#tbl:wide}

| Параметр | Описание |
|----------|----------|
| Пример | Данные |

:::
```

Блок внутри `.landscape` размещается на альбомных листах А4: поля сверху 30 мм, снизу 10 мм, слева и справа 20 мм (п. 7.1). После блока возвращается книжная ориентация, номера страниц продолжаются. Используй отдельные последовательные блоки, не вкладывай `.landscape` друг в друга. Эти вставки и `--page-start` работают со встроенным шаблоном.

### Типографика и проверки

Прямые кавычки `"…"` в русском тексте превращаются в «…», вложенные — в „…“; в английском — в “…” (п. 1.10). Длинные адреса ссылок (например, `URL: <https://…>` в списке источников) печатаются целиком и переносятся после «/», «.», «-», поэтому строки по ширине не растягиваются; сама ссылка не меняется. Переносы слов отключены, сноски вызывают предупреждение (п. 1.8). Валидатор, кроме структуры и ссылок, предупреждает о тире, набранном знаком минуса «–» (п. 1.11), о точке в конце названия таблицы или рисунка, о заголовках со строчной буквы, о пунктуации и регистре пунктов списков (п. 4.3, 4.4), о формуле без запятой перед «где», о малом числе источников и приложениях без ссылки. Текст автора конвертер не переписывает: это предупреждения.

### Оглавление и границы автоматизации

При наличии `# Аннотация` оглавление располагается после неё. Оно содержит структурные части, до трёх уровней разделов и сами приложения (без их разделов): основной шрифт 14 пт, интервал 1,5, без отступов, точечный заполнитель, номер справа (п. 3.2–3.4). При быстрой сборке вместо номеров стоит «—»: Word предложит обновить поля при открытии. С `--paginate` номера уже заполнены по измеренной вёрстке.

Все свойства абзацев, шрифтов, таблиц и разделов записываются в порядке схемы OOXML: Word, в отличие от LibreOffice, пропускает свойства не на своём месте. Для `.docx`, собранного с `--template`, сохраняются настройки пользовательского reference-документа; встроенный профиль поверх них не накладывается. Нумерация заголовков и медиа по Markdown-конвенциям продолжает работать.

Утилита оформляет предоставленный материал: аннотацию, источники, пояснения формул, расчёты, сканы и подписи она не сочиняет. Ссылки остаются кликабельными, но печатаются чёрным без подчёркивания.

### Проверка изменений в исходниках

```bash
uv run --extra dev --extra pagination pytest tests/ -q
uv run md2gost convert tests/fixtures/formatting/diploma.md --no-title-page -o build/check.docx
```

Проверочный документ охватывает подписи, прямые и опережающие ссылки, формулы основной части и приложения с пояснениями «где», таблицу обозначений с формулами в ячейках, длинный листинг, многостраничную альбомную таблицу и возврат к книжной ориентации. Тест с LibreOffice пропускается, если `soffice` не установлен.

## Использование с Claude Code

[Claude Code](https://claude.ai/code) — AI-ассистент в терминале, который умеет писать и редактировать отчёты за тебя.

### Установи скилл (один раз)

Скилл — это инструкция для Claude, как правильно писать отчёт по ГОСТ. Добавь alias в `~/.zshrc` (или `~/.bashrc`):

```bash
echo 'alias gost-skill="mkdir -p .claude/commands && curl -sL https://raw.githubusercontent.com/WithSoull/md2gost/main/.claude/commands/write-report.md -o .claude/commands/write-report.md && echo write-report skill installed"' >> ~/.zshrc
source ~/.zshrc
```

### Используй

1. Перейди в директорию с проектом, где нужен отчёт:

```bash
cd ~/my-project
```

2. Установи скилл в этот проект:

```bash
gost-skill
```

3. Запусти Claude Code и вызови скилл:

```bash
claude
```

В чате набери:

```
/write-report
```

Claude задаст вопросы про тему, автора, разделы — и сгенерирует готовый `.md` файл, а затем сам сконвертирует его в `.docx`.

### Что умеет скилл

- Задаёт вопросы и генерирует полноценный `.md` по ГОСТ 7.32
- Правильно оформляет рисунки, таблицы, формулы, листинги
- Автоматически запускает `md2gost convert` после генерации
- Можно попросить отредактировать уже существующий отчёт
